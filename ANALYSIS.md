# Environments and the Toy Evaluator

We traced the scope-discrimination form from the coursesite, the nested "let" that returns 3 under lexical scope and 101 under dynamic scope, with our eval-expr starting with an empty environment. First, the outer "let" evaluates "2" in the empty environment, so eval-let extends it, through extend-env, to "((x . 2))". The next "let" has a lambda as its initializer, so eval-expr takes the "lambda" branch.

The line that captures the defining environment is "(make-closure (second expr) (third expr) env)" in this lambda branch. make-closure returns "(list :closure params body env)". At that moment env holds only "((x . 2))", because the binding for "f" isn't in it yet. eval-let evaluates every initializer before it binds any name. Considering the aforementioned, the "x" bound to 100 does not exist yet either, so the closure keeps the "x" which holds 2. Afterward, the environment grow. It becomes "((x . 100) (f . closure) (x . 2))", but the closure's saved environment stays as "((x . 2))" because "extend-env" uses append and never modifies the given list. From the "(f 1)" call, apply-closure builds "((y . 1) (x . 2))" from "cenv", or the captured environment, and then goes on to evaluate "(+ x y)" as 2 plus 1, which gives 3.

Suppose apply-closure extended the caller's environment instead of the captured one. The body would then run in "((y . 1) (x . 100) (f . closure) (x . 2))". "lookup" returns the first match it finds, which is the "x" holding 100, so the answer would be 101 instead of 3. The language would become dynamically scoped, because a function would see the variables of whoever calls it, not the ones from where it was written.

CLISP is a Lisp-2, so it keeps variables and functions in separate namespaces. A variable that holds a function can't be called through "(f 3)" as CLISP looks for a function named "f", not the variable, so we write "(funcall f 3)" instead. In the same way, "#'cons" gets the function out of its namespace so it can be handed to "mapcar" in extend-env. Our toy language has only one environment. In the call branch, "(eval-expr (car expr) env)" evaluates the head "f" like any other expression. Because "f" is a symbol, eval-expr takes its symbol branch and passes it to lookup, which finds "(f . closure)" in the single environment and returns the closure. This means that in our toy language, "f" can hold a closure and be called directly as "(f 1)", with no need for a "funcall".
